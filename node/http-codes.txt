HTTP status codes as a vocabulary — 201 created, 200 ok, 204 no content (delete success with empty body), 400 bad input, 401 not authenticated, 403 authenticated-but-forbidden, 404 not found, 409 conflict. Using them precisely is a maturity signal.
PUT is idempotent, POST is not. Calling PUT /departments/1 with the same body ten times leaves the same result; ten POSTs create ten rows. DELETE is idempotent too (deleting an already-deleted thing is still "gone"). Interviewers ask this constantly.
Offset pagination and its scaling flaw (strong point): LIMIT ? OFFSET ? is simple but OFFSET 100000 forces MySQL to scan and discard 100,000 rows before returning — it gets linearly slower the deeper you page. The scalable alternative is keyset (cursor) pagination: WHERE id > ? ORDER BY id LIMIT ?, which jumps straight to the position using the index. Offset is fine for small admin UIs; keyset is what you use for large or infinite-scroll datasets. Knowing when each applies is the answer they want.
